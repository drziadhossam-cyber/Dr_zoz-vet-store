# Dr_Zoz Vet Store

منصة إلكترونية (واجهة أمامية فقط، بدون أي تكلفة استضافة) باسم Dr_Zoz Vet Store لعرض المنتجات البيطرية في مصر، مع إمكانية الاستفسار عن التوفر عبر WhatsApp.

**ملاحظة مهمة:** لا يعرض هذا الموقع أي أسعار في أي مكان، لا في بطاقات المنتجات ولا في صفحة التفاصيل ولا في رسائل واتساب. الهدف من الموقع هو العرض والتعريف بالمنتجات وتسهيل الاستفسار عن توفرها فقط.

هذا المشروع **Static بالكامل**: صفحات HTML، ولا يحتاج أي سيرفر أو قاعدة بيانات أو API مدفوع.

---

## 0. تصميم المشروع الآن: كل صفحة ملف واحد مكتفٍ ذاتيًا (أهم تغيير)

بعد عدة محاولات فشلت فيها بعض الاستضافات في تحميل ملفات CSS/JS بشكل منفصل (رغم كونها موجودة في نفس المجلد)، تم إعادة بناء المشروع على مبدأ مختلف تمامًا لضمان عدم تكرار المشكلة **مهما كانت طريقة الرفع**:

- **كل صفحة HTML (index.html، cart.html، إلخ) تحتوي التنسيق (CSS) والبرمجة (JavaScript) بداخلها مباشرة** — لا يوجد ملف `style.css` أو `app.js` منفصل يتم تحميله من الصفحة. حتى لو رُفع ملف HTML واحد فقط بمفرده على أي استضافة، سيظهر بكامل تصميمه وتفاعله الصحيح.
- **صور المنتجات الـ127 مضمّنة مباشرة داخل `products.json`** نفسه (بصيغة Base64) بدل أن تكون ملفات SVG منفصلة يمكن أن تُفقد أثناء الرفع.
- **الملف الخارجي الوحيد الذي يبقى ضروريًا هو `products.json`** — وهذا مقصود: هو الملف الذي تريد تعديله بنفسك لاحقًا (إضافة منتجات، تغيير رقم واتساب...)، فمن المنطقي أن يبقى ملفًا مستقلًا سهل التعديل، بدل دفنه داخل كل صفحة.
- إذا فشل تحميل `products.json` لأي سبب (لم يُرفع، أو الاستضافة أرجعت صفحة أخرى بدلًا منه)، **سيظهر الآن شريط تنبيه أحمر واضح أعلى الصفحة** يخبرك بالمشكلة تحديدًا، بدل ما يفشل الموقع بصمت.

ملفات `style.css` و`whatsapp.js` و`cart.js` و`products.js` و`search.js` و`app.js` لا تزال موجودة في المشروع كـ**ملفات مصدر** (Source files) — منها يتم توليد كل صفحة HTML عند أي تعديل مستقبلي في التصميم أو البرمجة، لكن المتصفح لا يحمّلها مباشرة ولا يعتمد عليها في العرض.

```

├── veterinary-medicines.html   قسم الأدوية البيطرية
├── veterinary-tools.html       قسم الأدوات والمستلزمات
├── product.html                صفحة تفاصيل المنتج (ديناميكية عبر ?id=)
├── cart.html                   قائمة الاستفسار (بدون أسعار أو إجمالي)
├── categories.html             تصفح حسب نوع الحيوان
├── about.html                  من نحن
├── contact.html                 تواصل معنا
├── privacy.html                 سياسة الخصوصية
├── terms.html                   الشروط والأحكام
├── disclaimer.html              إخلاء المسؤولية
├── products.json                كل بيانات المنتجات (127 منتجًا، بالصور مضمّنة) + إعدادات الموقع
├── placeholder.svg               صورة احتياطية عامة (غير حرجة لعمل الموقع)
├── robots.txt / sitemap.xml      ملفات SEO أساسية

```

كل ملف HTML يعمل بشكل مستقل تمامًا — الملف الوحيد الذي يجب أن يكون موجودًا بجانبه ليعمل الموقع بكامل وظائفه هو `products.json`.

## 2. عدد المنتجات وتصنيفها

يحتوي `products.json` حاليًا على **127 منتجًا بيطريًا حقيقيًا ومعروفًا** (وليس بيانات وهمية)، موزّعة كالتالي:

**الأدوية البيطرية (58 منتج):**
مضادات حيوية، أدوية طفيليات وديدان، فيتامينات ومكملات، مطهرات، أدوية أخرى.

**الأدوات والمستلزمات (69 منتج):**
مستلزمات العيادات، سرنجات وإبر، قفازات، شاش وقطن، مستلزمات طبية عامة، مستلزمات مزارع، مستلزمات حيوانات أليفة، مستلزمات دواجن، مستلزمات أبقار وأغنام وماعز، مستلزمات خيول.

كل منتج يحتوي: الاسم، الشركة المصنعة (أو "غير متوفر حاليًا" إن لم تكن معروفة بثقة)، الفئة، الحيوان المستهدف، وصف مختصر، الاستخدام العام، وصورة توضيحية مضمّنة. **لا يوجد أي حقل سعر في قاعدة البيانات إطلاقًا.**

### بخصوص الصور — مهم
لم يتم استخدام صور فوتوغرافية حقيقية لعبوات المنتجات، لأن معظم صور العبوات والمنتجات البيطرية التجارية (Baytril، Ivomec، Frontline، BD، إلخ) هي ملكية فكرية وتصوير منتج مملوك لشركاتها المصنّعة أو للمتاجر التي تبيعها، ولا يمكن تأكيد ترخيص استخدامها بشكل موثوق عبر هذه الأداة. بدلًا من ذلك، كل منتج له **صورة توضيحية مستقلة خاصة به** (وليست صورة تصنيف عامة مشتركة)، مكتوب عليها اسم المنتج نفسه + أيقونة تناسب تصنيفه، وتوضّح بشكل صريح أنها "صورة توضيحية — لا تمثل عبوة حقيقية". هذه الصور مضمّنة الآن مباشرة داخل `products.json` (Base64) فلا يمكن أن تُفقد بشكل منفصل عن باقي البيانات.

يمكنك استبدال أي صورة بصورة حقيقية موثوقة الحقوق لاحقًا — راجع الخطوة 3 أدناه لطريقة ذلك.

## 3. ماذا أفعل بعد نسخ الملفات؟ (خطوة بخطوة لمبتدئ تمامًا)

### الخطوة 1: جرّب الموقع على جهازك أولًا

المتصفح أحيانًا يمنع تحميل ملف `products.json` عند فتح `index.html` مباشرة بالنقر المزدوج (بروتوكول `file://`). لذلك شغّل خادمًا محليًا بسيطًا للتجربة:

**إذا كان عندك Python مثبت (يأتي مع ويندوز 10/11 ومعظم أجهزة Mac):**
1. افتح مجلد المشروع في الطرفية (Terminal / Command Prompt).
2. نفّذ الأمر:
   ```
   python -m http.server 8000
   ```
3. افتح المتصفح على: `http://localhost:8000`

**أو باستخدام إضافة VS Code:**
- ثبّت إضافة "Live Server" في Visual Studio Code، ثم اضغط بزر الفأرة الأيمن على `index.html` واختر "Open with Live Server".

بعد النشر الفعلي على أي استضافة حقيقية (وليس `file://`)، لن تحتاج لأي من هذا — الموقع سيعمل مباشرة.

### الخطوة 2: عدّل بيانات الموقع الأساسية

افتح ملف `products.json` وعدّل قسم `"settings"` في أعلى الملف:

```json
"settings": {
  "whatsappNumber": "201025739833",
  "contactEmail": "info@example.com",
  ...
}
```

- ضع رقم واتساب فعلي بصيغة دولية بدون علامة + وبدون مسافات (رقم الموقع الحالي 01025739833 مُخزَّن كـ `201025739833`).
- عدّل البريد الإلكتروني والعنوان ومواعيد العمل.

### الخطوة 3: عدّل أو أضف منتجات

كل منتج داخل `"products"` في نفس الملف عبارة عن كائن JSON بهذا الشكل:

```json
{
  "id": "med-001",
  "category": "medicines",
  "subcategory": "مضادات حيوية",
  "name": "اسم المنتج",
  "company": "الشركة المصنعة أو غير متوفر حاليًا",
  "animal": ["أبقار", "أغنام"],
  "description": "وصف مختصر للمنتج",
  "usage": "الاستخدام العام للمنتج",
  "image": "data:image/svg+xml;base64,....",
  "featured": false
}
```

- **لا تضف أي حقل سعر** — الموقع مصمم بالكامل بدون أسعار، وإضافة حقل سعر لن يظهر في الواجهة أصلًا لأن الكود لا يعرضه.
- لا تكتب اسم شركة أو معلومة لست متأكدًا منها — استخدم "غير متوفر حاليًا" بدلاً من التخمين.
- **لتغيير صورة منتج بصورة حقيقية:** أسهل طريقة هي استضافة الصورة على أي مكان (مثلاً رفعها كملف منفصل بجانب باقي الملفات، أو استخدام رابط مباشر موثوق)، ثم كتابة مسارها أو رابطها في `"image"` بدل النص الطويل الحالي، مثلاً: `"image": "product-01.jpg"` (إذا رفعت الملف بجانب باقي ملفات المشروع) أو رابط كامل يبدأ بـ `https://`. تأكد أن لديك حق استخدام الصورة قبل نشرها.

### الخطوة 4: انشر الموقع مجانًا

#### الخيار الأول: Cloudflare Pages
1. سجّل الدخول على [dash.cloudflare.com](https://dash.cloudflare.com).
2. من القائمة الجانبية: **Compute (Workers) ← Workers & Pages**.
3. اضغط **Create**، ثم اختر تبويب **Pages** (وليس Workers).
4. اختر **Upload assets / Direct Upload**.
5. حدّد **كل ملفات المشروع** (Ctrl+A داخل المجلد) واسحبها لمنطقة الرفع — أهم شيء أن يكون `products.json` من ضمن الملفات المحددة، فهو الملف الوحيد الضروري غير ملفات HTML.
6. اضغط **Deploy site**.

#### الخيار الثاني: static.app (الأسرع والأضمن)
اذهب إلى [static.app](https://static.app) واسحب ملف الـ **ZIP** الخاص بالمشروع كما هو (بدون فك الضغط) — يصبح الموقع مباشرًا فورًا بكل ملفاته، بدون تسجيل حساب وبدون احتمال نسيان أي ملف.

#### الخيار الثالث: GitHub Pages
1. أنشئ حسابًا مجانيًا على [github.com](https://github.com) إن لم يكن لديك.
2. أنشئ Repository جديد وارفع كل ملفات المشروع.
3. من `Settings > Pages` اختر Branch: `main` والمجلد `/root`.
4. سيظهر رابط الموقع بصيغة: `https://username.github.io/repo-name/`

بعد النشر، افتح `robots.txt` و`sitemap.xml` وغيّر `example.com` إلى رابط موقعك الحقيقي.

## 4. كيف يعمل الاستفسار عبر WhatsApp؟

- رابط "Click-to-Chat" العادي (`wa.me`) وهو مجاني تمامًا، بدون أي API مدفوع.
- رسالة المنتج الواحد بالصيغة بالضبط:
  > مرحبًا، أريد الاستفسار عن توفر منتج: [اسم المنتج]
- **لا يوجد أي سعر في أي رسالة واتساب.**
- من صفحة قائمة الاستفسار (`cart.html`) يمكن تجميع أكثر من منتج وإرسال استفسار واحد بالأسماء والكميات فقط.

## 6. استكشاف الأخطاء

### الموقع يظهر بدون تنسيق (روابط زرقاء، بدون ألوان أو تخطيط)
بعد التحديث الحالي هذا **لم يعد ممكن الحدوث** لأن كل صفحة تحمل تصميمها بداخلها. إذا حدث هذا الآن، فالسبب على الأغلب أنك ترفع نسخة قديمة من المشروع — تأكد من استخدام أحدث نسخة تم تسليمها لك.

### شريط أحمر أعلى الصفحة يقول "تعذّر تحميل بيانات المنتجات"
هذا يعني أن ملف `products.json` تحديدًا لم يُرفع أو لم يوجد بجانب صفحة HTML التي تفتحها. تأكد أنه مرفوع في نفس المجلد الذي رفعت فيه ملفات HTML، بنفس الاسم بالضبط (حساس لحالة الأحرف: `products.json` وليس `Products.json`).

### كيف تتأكد يدويًا
افتح `https://رابط-موقعك/products.json` مباشرة في المتصفح — يجب أن يظهر نص JSON طويل يبدأ بـ `{`. لو ظهرت صفحة الموقع نفسها بدل ذلك، فالملف غير موجود على الاستضافة والمشكلة في طريقة الرفع وليست في الكود.

## 7. الانتقال لاحقًا لقاعدة بيانات حقيقية

المشروع الآن يعتمد على ملف `products.json` فقط. إذا رغبت لاحقًا في لوحة تحكم حقيقية، أو تحديث بيانات تلقائي، أو تسجيل دخول للعملاء أو الإدارة، يمكن استبدال طريقة تحميل البيانات (دالة `vmeLoadData` المضمّنة داخل كل صفحة) لتقرأ من خدمة مجانية مثل **Supabase** أو **Firebase** بدلاً من ملف JSON.

## 8. ملاحظات مهمة قبل النشر الفعلي

- المنتجات المدرجة حاليًا أسماء وشركات بيطرية حقيقية ومعروفة عالميًا (مثل Baytril وIvomec وFrontline)، لكن **يجب مراجعة توفرها الفعلي في مصر ومدى ترخيصها وتسجيلها الرسمي** مع الصيدلية/الجهة البيطرية المرخصة المتعاون معها قبل الإطلاق الفعلي.
- لا تكتب أن أي منتج "معتمد" أو أن الموقع "مرخص" إلا بمستند رسمي موثّق.
- الموقع لا يعرض أي أسعار بتصميمه — إضافتها مستقبلًا تتطلب تعديل الكود المصدري (`products.js`، `cart.js`، `whatsapp.js`) عن قصد ثم إعادة التوليد.
- راجع صفحات "الشروط والأحكام" و"سياسة الخصوصية" و"إخلاء المسؤولية" وحدّث أي بيانات تواصل فيها.
- هذا المشروع لا يقدّم استشارة قانونية أو بيطرية؛ يُنصح بمراجعة جهة قانونية أو الهيئة المصرية للدواء البيطري بخصوص متطلبات عرض المنتجات الدوائية أونلاين قبل الإطلاق الفعلي.
